### Что уже работает

- 20 MCP-инструментов: 6 по справке платформы и 14 по выгрузке.
- Справка платформы: `search`, `info`, `getMember`, `getMembers`, `getConstructors`, `status`.
- Выгрузка: `dumpOpen`, `dumpSearch`, `dumpMetadata`, `dumpCode`, `dumpGrep`,
  `dumpEntrypoints`, `dumpCheck`, `dumpNode`, `dumpNeighbors`, `dumpTypes`,
  `dumpRights`, `dumpSimilar`, `dumpConventions`, `dumpReload`.
- `dumpMetadata` отдаёт `usages`: кто читает объект в коде и запросах.
- `dumpCheck`: неизвестные процедуры, число аргументов, отсутствующие метаданные,
  неиспользуемые переменные/параметры, функция без `Возврат`, дубли процедур.
- Граф вызовов в таблице `calls`; цели разрешаются для своего модуля и `ОбщийМодуль.Метод`.
- Права ролей и RLS-условия из `Roles/*/Ext/Rights.xml`.
- Расширения: `--dump "база;расширение"`, файл расширения перекрывает базу по относительному пути.
- Наблюдение: `DUMP_WATCH_SECONDS`, частичное обновление изменившихся `.bsl`,
  остальные изменения — полная перестройка.
- Схема индекса: `DumpIndex.SCHEMA_VERSION = 7`.
- 121 тест, `ktlintCheck` чистый, jar собирается под Java 17.

## Что осталось

### 1. FTS/триграммы для `grep` — главное недостающее

Сейчас `dumpGrep` берёт список модулей из индекса и читает файлы на каждый запрос.
Полнотекстового индекса, как в Data1C, нет.

Сделать:

- таблицу FTS5 (`modules_fts` с `trigram` или `unicode61`) в схеме v8;
- заполнение при индексации и частичном обновлении;
- поиск подстроки/слов через FTS, regex — fallback по файлам;
- учесть размер индекса (FTS заметно увеличит 747 МБ);
- тест на регистр, кириллицу, спецсимволы и regex-fallback.

Файлы: `DumpIndexer.kt`, `DumpIndex.kt`, `DumpService.grep`, `DumpStorage`.

### 2. Частичная переиндексация метаданных

Сейчас частично обновляются только `.bsl`; изменение `*.xml`, форм, ролей, подписок
и заданий вызывает полную перестройку.

Сделать:

- дифф XML по mtime/hash;
- обновление `objects`, `fields`, `modules`, `entrypoints`, `roles` без полного прохода;
- каскадную инвалидацию зависимых модулей;
- тест: изменить реквизит/форму — карточка и точки входа обновились, индекс не пересобран целиком.

Файлы: `DumpIndexer.kt`, `DumpStorage.startWatcher`, `MetadataXmlParser.kt`.

### 3. Полный вывод типов в `dumpTypes`

Сейчас выводятся только литералы, `Новый`, ссылки на метаданные. Нет типов возврата
функций, выражений, иерархии типов и платформенных типов.

Сделать:

- типы возврата своих функций (`Возврат`);
- простые выражения (`А + Б`, `СтрШаблон`, `ОбщегоНазначения.Метод()`);
- ссылочные типы платформы и коллекции (`Массив`, `Структура`, `ТаблицаЗначений`);
- тесты на типичные конструкции BSL;
- не выдавать ложный тип, если вывод неоднозначен.

Файлы: `BslParser.kt`, `DumpGraphService.types`, `DumpJsonService.types`.

### 4. Объектная модель расширений

Сейчас расширение — это только перекрытие файлов по относительному пути. Новые объекты
и реквизиты расширения не появляются в карточках метаданных.

Сделать:

- слияние объектов/реквизитов/форм из расширения в карточку базы;
- пометка источника (`base`/`extension`) и конфликтов;
- правила приоритета как в 1С;
- тест: расширение добавляет реквизит — `dumpMetadata` его показывает.

Файлы: `DumpIndexer.effectiveSources`, `MetadataXmlParser.kt`, `DumpService.metadata`.

### 5. Граф вызовов: внешние и динамические вызовы

Сейчас `Объект.Метод`, вызовы через переменные и обработчики форм остаются внешними.

Сделать:

- разрешать методы объектов по выведенному типу;
- связать обработчики форм из `entrypoints` с процедурами модуля формы;
- помечать динамические вызовы как `dynamic`, а не просто `external`;
- тест на `СправочникСсылка.Метод` и обработчик формы.

Файлы: `DumpGraphService`, `DumpIndexer.resolveCall`, `BslParser`.

### 6. Конвенции: полный каталог и настройка

Сейчас 6 эвристик: серверный `Сообщить`, запрос/запись в цикле, `Попытка` без
`Исключение`, `ВызватьИсключение` без текста, TODO.

Сделать:

- каталог конвенций с id, описанием, уровнем;
- включать/выключать правила в конфигурации;
- подавление (`// noinspection` или аналог);
- тесты на каждое правило;
- не выдавать предупреждение там, где правило не применимо.

Файлы: `DumpConventionsService.kt`, `DumpJsonService.conventions`.

### 7. Права: эффективные права и проверка RLS

Сейчас есть разбор прав и фильтр по условию, но нет эффективных прав и анализа ролей.

Сделать:

- эффективные права по нескольким ролям;
- сравнение ролей;
- проверка RLS-условий на пустые/подозрительные конструкции;
- тест на роль с RLS и ролью без прав.

Файлы: `RightsParser.kt`, `DumpRightsService.kt`, `DumpIndex.rights`.

### 8. `dumpSimilar`: качество и кэш

Сейчас — эвристика по общим вызовам и метаданным, без кэша и семантики.

Сделать:

- веса признаков (вызовы, метаданные, имя, размер);
- кэш признаков рутин;
- объяснение похожести в ответе;
- тесты на ложные срабатывания.

Файлы: `DumpSimilarService.kt`, `DumpIndex`.

### 9. Watch: надёжность

Сейчас наблюдение опирается на `ConfigDumpInfo.xml` и mtime `.bsl`, без `WatchService`.

Сделать:

- `WatchService` с debounce;
- сквозной тест: изменить модуль на диске — `dumpCode`/`dumpNeighbors` видят новое;
- обработка удаления/переименования;
- не блокировать запросы во время обновления.

Файлы: `DumpStorage`, `DumpIndexer.updateModules`.

### 10. Размер и скорость индекса

747 МБ и 46,9 с — приемлемо, но есть запас.

Сделать:

- оценить FTS и `VACUUM`;
- убрать лишние индексы/дубли;
- замерить холодный/горячий старт;
- сравнить с Data1C.

### 11. Тесты и CI

- Нет тестов на `dumpConventions` и watcher.
- Нет e2e-теста частичной переиндексации через `DumpStorage`.
- Проверить интеграционные тесты на Linux/macOS (сейчас проверялось на Windows).
- Добавить CI: `ktlintCheck`, `test` с `PLATFORM_PATH`, `bootJar`.
