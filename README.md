# MCP-сервер для 1С: справка по платформе и разбор выгрузки конфигурации

**MCP (Model Context Protocol) сервер** для AI-ассистентов. Две возможности в одном процессе:

1. **Справка по API платформы 1С:Предприятие** из установленного синтакс-помощника (`.hbk`):
   методы, типы, сигнатуры, параметры, конструкторы, перечисления.
2. **Разбор выгрузки конфигурации** («Выгрузить конфигурацию в файлы»): объекты метаданных,
   реквизиты, табличные части, формы, модули и процедуры, поиск по тексту модулей.

Всё отдаётся в JSON, который удобно читать модели. Сервер не меняет ни выгрузку, ни установленную
платформу: только читает файлы.

## Что умеет

- **Двадцать инструментов**: шесть по справке (`search`, `info`, `getMember`, `getMembers`,
  `getConstructors`, `status`) и четырнадцать по выгрузке (`dumpOpen`, `dumpSearch`, `dumpMetadata`,
  `dumpCode`, `dumpGrep`, `dumpEntrypoints`, `dumpCheck`, `dumpNode`, `dumpNeighbors`, `dumpTypes`,
  `dumpRights`, `dumpSimilar`, `dumpConventions`, `dumpReload`).
- **Структурная справка**: сигнатуры с параметрами (обязательность, типы, описания), возвращаемые
  значения, примеры и примечания; для типа — методы, свойства и конструкторы; для перечисления — значения.
- **Поиск по имени, английскому имени и описанию** с ранжированием и подсказками при опечатках;
  понимает запись «Тип.Член» (`Массив.Добавить`).
- **Поиск установленной платформы**: несколько версий, выбор самой свежей или заданной, язык `ru`/`en`.
- **Разбор выгрузки**: объекты, реквизиты, табличные части, формы, команды, макеты, значения
  перечислений; модули и процедуры; `dumpCode` и `dumpGrep` по тексту.
- **Ссылки на метаданные**: `dumpMetadata` показывает, кто и где читает объект в коде и запросах
  (`usages`: контекст, модуль, процедура, строка).
- **Точки входа**: обработчики форм, подписки, регламентные задания, HTTP- и веб-сервисы
  (`dumpEntrypoints`), с фильтром по объекту.
- **Проверка кода**: `dumpCheck` для модуля или черновика — неизвестные процедуры, число аргументов,
  отсутствующие метаданные, неиспользуемые переменные и параметры, функция без `Возврат`.
- **Граф вызовов**: `dumpNode` (карточка процедуры/модуля/объекта), `dumpNeighbors` (входящие и
  исходящие вызовы, обращения к метаданным), `dumpTypes` (таблица символов с выводом типов).
- **Права и RLS**: `dumpRights` — права ролей на объекты и условия ограничения доступа.
- **Похожие процедуры**: `dumpSimilar` — по общим вызовам и объектам метаданных.
- **Конвенции**: `dumpConventions` — «Сообщить» на сервере, запрос/запись в цикле, пустая `Попытка`.
- **Расширения**: `--dump "база;расширение"` — файлы расширения перекрывают базу по относительному пути.
- **Наблюдение**: `DUMP_WATCH_SECONDS` — при изменении выгрузки перечитывает изменившиеся `.bsl`;
  метаданные, формы и роли требуют полной перестройки.
- **SQLite-индекс выгрузки**: строится один раз (6,1 ГБ выгрузки — около 47 секунд, индекс 747 МБ)
  и переиспользуется при следующем запуске.
- **Дисковый кэш разбора справки**: повторный старт читает модель за доли секунды вместо разбора 39 МБ.
- **Фоновая загрузка**: `status` отвечает сразу, инструменты ждут готовности ограниченное время
  и честно сообщают `platform_not_ready`/`dump_not_ready`, если разбор ещё идёт.
- **Ограничение размера ответа** (24 000 знаков по умолчанию) с продолжением по `offset`/`nextOffset`.
- Два транспорта: **stdio** (по умолчанию) и **SSE** для сетевого доступа.

## Быстрый старт

> Для сборки и запуска нужен **JDK 21+**. Проект собирается с `jvmToolchain(21)`.

```bash
# сборка; clean убирает jar-файлы прошлых версий
./gradlew clean bootJar
```

**bash (Linux, macOS, Git Bash):**

```bash
jar=$(ls -t build/libs/mcp-bsl-context-*.jar | head -1)

# stdio: платформа ищется в стандартных каталогах ОС
java -Dfile.encoding=UTF-8 -jar "$jar"

# явный путь к установленной платформе
java -Dfile.encoding=UTF-8 -jar "$jar" \
  --platform-path "/opt/1cv8/x86_64/8.3.27.2214"

# вместе с выгрузкой конфигурации
java -Dfile.encoding=UTF-8 -jar "$jar" \
  --platform-path "/opt/1cv8/x86_64/8.3.27.2214" \
  --dump "/path/to/dump"
```

**PowerShell (Windows):**

```powershell
$jar = (Get-ChildItem build/libs/mcp-bsl-context-*.jar |
        Sort-Object LastWriteTime | Select-Object -Last 1).FullName

# stdio: платформа ищется в стандартных каталогах ОС
java "-Dfile.encoding=UTF-8" -jar $jar

# явный путь к установленной платформе
java "-Dfile.encoding=UTF-8" -jar $jar `
  --platform-path "C:\Program Files\1cv8\8.3.27.2214"

# вместе с выгрузкой конфигурации
java "-Dfile.encoding=UTF-8" -jar $jar `
  --platform-path "C:\Program Files\1cv8\8.3.27.2214" `
  --dump "D:\dump\1c_files"
```

В PowerShell два отличия от bash:

- ключ `-D...` берите в кавычки. Литеральный аргумент вида `-имя.имя` PowerShell разбирает на два
  (`-Dfile` и `.encoding=UTF-8`), и Java отвечает `Could not find or load main class .encoding=UTF-8`;
- продолжение строки — обратный апостроф (`` ` ``), а не `\`. Проще писать команду одной строкой.

Путь к платформе можно не указывать, если 1С установлена в `C:\Program Files\1cv8` или
`/opt/1cv8` — сервер найдёт самую свежую версию. Выгрузку можно не указывать и открыть позже
инструментом `dumpOpen`.

В режиме stdio процесс молча ждёт JSON-RPC на stdin: это нормально, его запускает MCP-клиент.
Для проверки вручную используйте `--help` или `--benchmark` (см. [Замеры справки](#замеры-справки)).

## Инструменты

Каждый инструмент возвращает JSON-объект. У найденного элемента всегда есть `kind`
(`method`, `property`, `type`, `enum`, `enum_value`), у страниц — `total`, `returned`,
`nextOffset`, `hasMore`; если ответ сокращён по размеру, добавляется `truncated` и подсказка.

| Инструмент | Что делает | Основные аргументы |
|---|---|---|
| `search` | ищет методы, свойства, типы, перечисления и их значения; возвращает владельца (`owner`) и короткое описание | `query`, `type`, `limit` (1–50), `offset` |
| `info` | точная карточка: сигнатуры, параметры, возвращаемый тип, примеры, примечания; для типа — счётчики и состав, для перечисления — значения | `name`, `type` |
| `getMember` | метод, свойство или значение перечисления конкретного типа | `typeName`, `memberName` |
| `getMembers` | состав типа страницей (у перечисления — значения) | `typeName`, `limit` (1–500), `offset` |
| `getConstructors` | варианты `Новый <Тип>(...)` с параметрами | `typeName`, `limit` (1–100), `offset` |
| `status` | состояние сервера: справка и выгрузка, версии, размеры, кэш, установленные платформы, список инструментов | — |

### Выгрузка конфигурации

Эти инструменты работают после `--dump` или `dumpOpen`.

| Инструмент | Что делает | Основные аргументы |
|---|---|---|
| `dumpOpen` | открыть выгрузку и построить (или переиспользовать) индекс | `path` |
| `dumpSearch` | объекты, реквизиты и процедуры; владелец и путь | `query`, `kind`, `limit` (1–100), `offset` |
| `dumpMetadata` | карточка объекта: реквизиты, табличные части, формы, команды, макеты, значения перечисления, модули и процедуры; `usages` — кто читает объект в коде и запросах | `ref` (`Catalog.Номенклатура`), `limit` (1–500) |
| `dumpCode` | текст модуля с номерами строк | `path` или `id`, `from`, `to` |
| `dumpGrep` | поиск по тексту модулей: подстрока или regex, с владельцем и процедурой | `pattern`, `regex`, `ignoreCase`, `extensions`, `paths`, `context`, `limit`, `deadlineMs` |
| `dumpEntrypoints` | обработчики форм, подписки, задания, HTTP/веб-сервисы | `kind` (`form`, `subscription`, `job`, `http`, `web`), `metadata`, `limit` |
| `dumpCheck` | проверка модуля или черновика: процедуры, аргументы, метаданные, неиспользуемые переменные, `Возврат` | `path`, `id`, `text` |
| `dumpNode` | карточка процедуры, модуля или объекта метаданных | `id` (`routine:123`, `module:45`, `Catalog.Номенклатура`) |
| `dumpNeighbors` | входящие/исходящие вызовы и обращения к метаданным | `id`, `direction`, `kinds`, `limit` |
| `dumpTypes` | таблица символов модуля с выводом типов | `path`, `id`, `text` |
| `dumpRights` | права ролей и условия RLS | `role`, `metadata`, `condition`, `limit` |
| `dumpSimilar` | похожие процедуры по вызовам и метаданным | `path`, `id`, `text`, `routine`, `limit` |
| `dumpConventions` | конвенции кода: серверный `Сообщить`, запрос/запись в цикле, `Попытка` | `path`, `id`, `text` |
| `dumpReload` | перестроить индекс после изменения файлов | — |

### Ошибки и подсказки

Ошибка приходит ответом, а не исключением протокола:

```json
{
  "error": {
    "code": "not_found",
    "message": "В справке платформы нет элемента с таким именем",
    "suggestions": ["СтрНайти", "СтрНачинаетсяС"],
    "memberOwners": ["Массив.Добавить"]
  }
}
```

Коды: `invalid_request`, `not_found`, `type_not_found`, `member_not_found`,
`platform_not_ready`, `platform_load_failed`, `internal`.

## Как сервер находит платформу

Порядок:

1. `--platform-path` — каталог установки, каталог версии или сам файл `shcntx_*.hbk`.
2. `--platform-root` — дополнительный корень поиска (можно повторять).
3. Переменные окружения `PLATFORM_CONTEXT_PATH`, `PLATFORM_ROOT`.
4. Стандартные каталоги ОС: `C:\Program Files\1cv8`, `C:\Program Files (x86)\1cv8` (Windows),
   `/opt/1cv8/x86_64`, `/opt/1cv8`, `/opt/1C/v8.3/x86_64` (Linux), `/opt/1cv8` (macOS).

Версия выбирается самая свежая; `--version 8.3.27` ограничивает поиск этой версией.
Язык задаётся `--locale ru|en`; если файла на нужном языке нет, сервер честно откатывается на `ru`.

## Кэш разбора

Разобранная модель хранится в JSON рядом с кэшем пользователя:

- Windows: `%LOCALAPPDATA%\mcp-bsl-context`
- Linux/macOS: `~/.cache/mcp-bsl-context` и `~/Library/Caches/mcp-bsl-context`

Кэш проверяется по пути, размеру, времени изменения `.hbk` и версии схемы; при обновлении платформы
он пересобирается сам. Управление: `--cache-dir <путь>`, `--no-cache`, `--refresh`.

## Индекс выгрузки конфигурации

Выгрузка разбирается в SQLite-индекс: объекты метаданных, реквизиты, табличные части, формы,
команды, макеты, значения перечислений, модули и процедуры. Индекс лежит отдельно от выгрузки —
`%LOCALAPPDATA%\mcp-bsl-context\dumps\dump-<hash>.db` (Linux/macOS — в каталоге кэша пользователя),
поэтому файлы выгрузки не меняются.

- Первое открытие строит индекс в фоне; `status` показывает фазу и прогресс.
- Повторный запуск с тем же `--dump` открывает готовый индекс за доли секунды.
- `dumpReload` перестраивает индекс после правок файлов на диске.
- Схема индекса версионирована: при обновлении сервера старый индекс пересобирается сам.

## Параметры запуска

```
-p, --platform-path <путь>   каталог установки, каталог версии или файл shcntx_*.hbk
    --platform-root <путь>   дополнительный корень поиска (ключ можно повторять)
    --version <версия>       нужная версия: 8.3.27 или 8.3.27.2214
    --locale <ru|en>         язык справки
    --cache-dir <путь>       каталог кэша
    --no-cache               не читать и не писать кэш
    --refresh                пересобрать кэш из .hbk
    --lazy                   начать разбор при первом запросе, а не при старте
    --dump <путь>            каталог выгрузки конфигурации
    --dump-index-dir <путь>  каталог SQLite-индексов выгрузки
-m, --mode <stdio|sse>       транспорт
    --port <порт>            порт SSE
-v, --verbose                отладочное логирование
    --benchmark              замеры и выход
-h, --help                   справка
```

Тесты трёх видов: юнит-тесты (маппинг, каталог, кэш, локатор, JSON, CLI), тесты выгрузки на
синтетическом дампе (индекс, поиск, карточка, код, grep) и интеграционные на реальной справке
установленной платформы.

Структура:

```
src/main/kotlin/com/alexqsoft/
  business/        домен: сущности, поиск, страницы, сервисы
  infrastructure/  hbk-парсер, локатор платформ, кэш, каталог; dump-парсер, SQLite-индекс
  presentation/    MCP-инструменты, JSON-ответы, CLI, бенчмарк
```

Подробности — в [документации](documentation/README.md).

## Ограничения

- Индексируется синтакс-помощник (`shcntx_*.hbk`). Описание встроенного языка и языка запросов
  (`shlang_*.hbk`, `shquery_*.hbk`) пока не разбираются.
- Модель платформы — снимок на момент запуска; после обновления 1С перезапустите сервер
  (кэш пересоберётся сам).
- Выгрузка — снимок на момент построения индекса: после правок вызывайте `dumpReload` или
  включите наблюдение (`DUMP_WATCH_SECONDS`). Наблюдение перечитывает только изменившиеся `.bsl`;
  изменения метаданных, форм и ролей перестраивают индекс целиком.
- Граф вызовов строится по именам: вызовы `Объект.Метод` и внешние методы остаются внешними узлами.
  `dumpTypes` выводит только простые типы (литералы, `Новый`, ссылки на метаданные).
- Неизвестные процедуры проверяются, только когда загружена справка платформы; для форм
  параметры-обработчики не считаются неиспользуемыми.
- Справка и выгрузка читаются только с локального диска.

## Идеи и лицензия

Алгоритм чтения справки базируется на идеях [bsl-context](https://github.com/1c-syntax/bsl-context)
(1c-syntax). Формат JSON-ответов, продолжение по `nextOffset`, инструмент `status`,
поиск установленных версий и каталог-ранжирование перенесены по мотивам
[Data1C](https://github.com/lyzhenko/data1c).
